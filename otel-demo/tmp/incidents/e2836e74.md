# Prior Finding: e2836e74

## Root Cause
`inventory-nearmiss.js` introduces a read-through cache (`stockCache`, TTL 5,000 ms) that is never invalidated after `inventory[item.id] -= item.quantity`. Combined with the inherited TOCTOU read-check-sleep-decrement pattern (no per-product mutex), the stale cache amplifies the race window by ~33× — from ~155 ms to 5,000 ms — allowing all three load-generator pods to read the same pre-decrement stock value, pass the guard check, and all decrement concurrently. This exhausted 50-unit products (driving 100–128 `StockMismatchError`/min across all 12 products) and drove product 7 (Ceramic Plant Pot, initial stock 5) into negative inventory.

## Fix Pattern
Two changes to `inventory-nearmiss.js`: (1) add `delete stockCache[item.id]` immediately after the decrement on line 64 to invalidate the stale cache entry on every write; (2) add a per-product promise-chain mutex (`withProductLock`) wrapping the read-check-sleep-decrement block inside `reserveInventory` to serialize concurrent coroutines for the same product. Fix 1 eliminates the 5,000 ms stale-read window (primary root cause); Fix 2 eliminates the residual TOCTOU race (co-root-cause). Together they fully prevent concurrent over-decrement at any load level.
