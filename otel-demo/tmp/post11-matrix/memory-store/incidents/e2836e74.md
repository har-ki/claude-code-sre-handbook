# Prior Finding: e2836e74

## Root Cause
The `inventory-nearmiss.js` variant introduces a 5-second read-through cache (`stockCache`) in `getStock()`. Concurrent checkout requests all see the same stale cached stock value, pass the `currentStock >= item.quantity` guard, wait through a 50–150 ms simulated business-rule delay, and then all decrement the in-memory inventory — driving it negative and triggering a `StockMismatchError`. This is a classic TOCTOU (Time-Of-Check / Time-Of-Use) race made reliable by the cache widening the window between read and write.

## Fix Pattern
After the async business-rule delay and before the decrement, re-read the live `inventory[item.id]` value directly (bypassing the cache) and abort with a retriable error if stock is no longer sufficient. This closes the TOCTOU window without removing the cache from the read path. Insert the live-stock re-validation guard between the `await new Promise(resolve => setTimeout(...))` at line 62 and the `inventory[item.id] -= item.quantity` decrement at line 64 of `src/services/inventory-nearmiss.js`.
